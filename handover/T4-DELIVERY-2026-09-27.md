## 本轮修复

Windows 检出时，6 款受摘要门禁保护的皮肤的 `NOTICE`，以及 trading 的 `LICENSE`，仍使用 CRLF。生产树摘要读取原始字节，门禁和锁文件使用 Git 规范化后的 LF，因此初次全量测试在 miku 摘要比较处失败。补齐 `.gitattributes` 的精确 LF 规则并按规则刷新这些文件后，全量测试通过；未改动摘要算法、锁定值或皮肤运行代码。

真实 Edge 渲染发现 `easySetup/readPersona result strict codec has no create() factory`：人设设置插件的 host/client 描述符仍用旧 `schema` 属性。两侧改为新内核的 `create()` 工厂，保留原有 JSON 透传语义；锁文件仅同步该插件的两处树摘要。新增 `easy-setup-typert.test.ts`，使用实际 Cordis/Typert 注册器验证两侧六个方法注册及 codec 行为。修复后的全量测试、真实渲染和人设 GUI 写入回读均已通过。

真实打包壳首次启动发现 `@deepseek-ai/dsh-client-ui-settings-general` 激活失败：rc.2 的 `DesktopUpdateSource` 会在构造时调用桌面桥的 `updates.status()`，而原桥只有旧的 `check/install/subscribe`。在 EAC 自有 `bridge.ts` 补齐 `status/open`，状态保持 idle，不启用客户端更新；原方法保留。`bridge-preload-parity.test.ts` 执行真实桥与当前内核消费者，防止普通浏览器无桌面桥时的漏测。Electron preload 在 beta 已删除，当前无需双侧文件修改。

深入检查启动告警发现，历史交接所称的 5 个“可选入口 import 失败”包含实际阻断默认会话的 `ptc-runtime`。`legacy-peer-deps=true` 不会自动安装这些 peer；`package.json` 显式补齐当前 overrides 已钉版的 `dsh-ptc-runtime`、`dsh-llm-deepseek`、`dsh-deepseek-account` 三个包及锁项。新增默认 host 入口真实 import 回归，5 个入口均恢复；干净 staging 的默认 standard 会话成功持久化。未修改内核源码，也未向模型发送请求。

构建复现注意：官方 NSIS ZIP 直链在本机超时，改用 `gh release download`，核验 Tauri 固定 SHA1 后放入其标准缓存；未跳过校验。便携包必须在 Tauri bundling **结束后**装配，因为 bundler 会临时将 EXE 的 bundle marker 从 `UNK` 改为 `NSS`，结束时恢复。`final-artifacts/` 才是最终交付目录，较早 `artifacts/` 的诊断包不能分发。

`fetch-kernel.js` 本机重打包产生的 234 处无关 package-lock integrity 差异已另存证据目录 `package-lock.local-kernel.json`，并恢复已有包的原始 Git 哈希；锁文件仅保留上述三个新依赖的必要变更。原生构建产物也已恢复，避免把本机二进制混入修复。再次依赖安装前应先重跑 fetch-kernel，让锁文件与本机 tarball 对齐。

项目技能分类器对 `.sync/plugins.lock.json` 返回 unmatched-code，并引用 beta 中已删除的 `companion-plugins-registry`、`plugin-slot-registration`、`onboarding-selection` 测试，因此输出 blocked。用户已明确同意使用本计划的实际测试入口继续，将分类器过期记录为交接问题；本轮未改动技能规则或把 blocked 报成通过。
