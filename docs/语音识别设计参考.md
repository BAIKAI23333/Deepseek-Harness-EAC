# 语音识别模块设计参考

> 本文档是对 JARVIS 语音识别（STT）模块的详细设计总结，覆盖**采集 → 转写 → 唤醒门控 → 提交**全链路，
> 并附带 TTS 输出层与配置/状态管理。所有参数以当前代码为准，出处标注在每节标题后。
>
> 核心源码：
> - 前端采集层：[web/src/lib/voice.ts](../web/src/lib/voice.ts)（`JarvisMic` 类）
> - 后端转写层：[jarvis/server/routes.py](../jarvis/server/routes.py)（`POST /api/stt`）
> - 后端 TTS：[jarvis/server/routes.py](../jarvis/server/routes.py)（`POST /api/tts`）
> - 配置 schema：[jarvis/config.py](../jarvis/config.py)（`VoiceConfig`）+ [config.yaml](../config.yaml)（`voice:`）
> - 前端状态：[web/src/lib/store.ts](../web/src/lib/store.ts)

---

## 1. 设计目标与原则

语音入口要回答四个问题：**何时录、是否理、说了什么、能不能打断**。由此拆出四条不可破坏的原则：

| # | 原则 | 含义 |
|---|---|---|
| P1 | 采集与识别分离 | 浏览器只负责「何时录 + 是否理」，服务端只负责「说了什么」，中间靠一个 HTTP 接口耦合 |
| P2 | 静默丢弃优先 | 环境噪音、语气词、非唤醒话语一律**丢弃而非提交**，宁可漏一次指令也不误触一次任务 |
| P3 | 逐级降级 | GPU→CPU、大模型→小模型、主路径→兜底路径，每级失败优雅落到下一级 |
| P4 | 常驻成本最小化 | 唤醒的代价是「常开麦克风 + 常驻模型」，选型/VAD 频率/显存都以「能长期挂着」为准绳 |

## 2. 总体架构与数据流

```
┌─────────────────────────── 浏览器（前端 voice.ts）───────────────────────────┐
│ getUserMedia(echoCancellation+noiseSuppression+autoGainControl)             │
│      │                                                                      │
│      ▼                                                                      │
│ WebAudio Analyser ──rAF 60fps──► 音量 VAD（动态基线阈值）                    │
│      │                               │ 音量越过阈值                          │
│      ▼                               ▼                                      │
│ MediaRecorder 录 webm/opus ──► 静音 900ms / 超时 8s ──► Blob                │
│      │                                                                      │
│      ▼  POST /api/stt (multipart: audio + language)                         │
│ 转写文本 → 幻觉/填充词过滤 → 唤醒词门控 → 片段合并 → WS 聊天管线              │
└──────────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────── 服务端（后端 routes.py）──────────────────────────┐
│ POST /api/stt                                                               │
│      │                                                                      │
│      ▼                                                                      │
│ 线程池(executor) ──► faster-whisper (ctranslate2)                           │
│                        ├─ GPU 路径: large-v3-turbo / float16                 │
│                        └─ CPU 路径: small / int8                             │
│      ▲                 （CUDA 探针决定走哪条，降级后钉死）                     │
│      │                                                                      │
│ VRAM 管理器 ◄───── 注册驱逐/恢复回调（与 FLUX 协调显存）                      │
└──────────────────────────────────────────────────────────────────────────────┘
```

**唯一跨端契约**：浏览器把音频 Blob 以 `multipart/form-data` POST 到 `/api/stt`，服务端返回
`{"text": "..."}`。两端可独立演进。

## 3. 前端采集层（[voice.ts](web/src/lib/voice.ts)）

### 3.1 音频源约束

`getUserMedia` 必须显式开启三项：

```js
audio: {
  echoCancellation: true,   // 关键：打断(barge-in)成立的前提，剥离 JARVIS 自己的 TTS 回声
  noiseSuppression: true,   // 降低环境噪音对 VAD 的干扰
  autoGainControl: true,    // 稳定输入电平
}
```

> 权衡：回音消除会削弱 TTS 自身的声音，这是「说话时听不清自己」的必要代价；关掉它 VAD 会把
> JARVIS 自己的语音当指令转录，导致自我对话死循环。

### 3.2 动态基线 VAD（语音活动检测）—— 核心算法

用「音量 vs 动态阈值」而非固定阈值判断说话：

```
每帧（rAF 60fps）：
  lvl = Analyser.getByteFrequencyData() 的平均 / 255        // 0~1 归一化音量

前 1 秒（BASELINE_WINDOW_MS）学习环境底噪，且只学「未在录音时」的样本
baselineLvl = 底噪的滚动均值

动态阈值 = max(绝对下限, 底噪 × 倍数)
voiceThr   = max(SILENCE_THRESHOLD, baselineLvl × BASELINE_MULTIPLIER)

状态转移：
  lvl > voiceThr                → 开始录音（若未在录）
  静音连续 > SILENCE_TIMEOUT_MS → 结束录音，提交转写
  录音时长 > MAX_RECORDING_MS   → 强制结束（用户一直没停）
```

| 参数 | 值 | 作用 |
|---|---|---|
| `SILENCE_THRESHOLD` | 0.05 | 绝对下限，防零底噪时阈值过低 |
| `BASELINE_WINDOW_MS` | 1000 | 学习底噪的时间窗 |
| `BASELINE_MULTIPLIER` | 1.8 | 底噪之上的裕度；越大越不易误触发 |
| `SILENCE_TIMEOUT_MS` | 900 | 静音判定句末的时长 |
| `MIN_RECORDING_MS` | 350 | 短于它的片段丢弃（咳嗽/点击） |
| `MAX_RECORDING_MS` | 8000 | 超长语音强制截断 |

分析器配置：`fftSize = 512`，`smoothingTimeConstant = 0.4`（对电平变化响应更快）。

### 3.3 录音生命周期

- 格式：`MediaRecorder` 录 `audio/webm;codecs=opus`，不支持时回退 `audio/webm`
- 分片：`start(100)`，100ms 一片，`ondataavailable` 累积
- 编码在浏览器硬件完成，不占 JS 主线程

### 3.4 唤醒词检测（三层匹配 + 中英双语）

Whisper 会把 "jarvis" 误听成 jorvis/jervis/charvis/yarvis…… 因此**不能用等值匹配**，用三层递进匹配：

| 层 | 机制 | 示例命中 |
|---|---|---|
| 1 严格正则 | `\b(?:hey|ok|…)?\s*j\.?a\.?r\.?v\.?i\.?s\.?\b` | "Hey J.A.R.V.I.S." |
| 2 形状正则 | `[jyhc]h?[aeiouy]+r?[vb][aeiouy]+s+` —— 语音学「辅音簇+元音」形态 | "charvis" |
| 3 编辑距离 | 对每个 token 算 Levenshtein ≤ 2 | "jarves" "jervis" |

语言分派（`detectWake`，由 `sttLang` 决定）：

| `sttLang` | 检测路径 |
|---|---|
| `en` | 仅英文（严格/形状/编辑距离） |
| `zh` | 仅中文：`(贾维斯|jia\s*wei\s*si|jiaweisi)` |
| `auto` | 中英都试（`detectWakeZh || detectWakeEn`） |

> 中文唤醒词用裸包含匹配而非 `\b`（CJK 字符不是 `\w`）。英文 "hey jarvis" 由英文路径处理，
> zh 模式下唤醒词刻意只保留中文形式。

`isJarvisLike` 的 token 过滤：长度 4~9、去除非字母后，先匹配语音家族正则，再算与 "jarvis" 的
编辑距离 ≤ 2。

唤醒词剥离（`stripWakeWord`）：提交前把唤醒词从文本里剥掉，让模型只看到命令主体；`auto` 模式
中英都剥一次，取剥得更短的那个结果。

### 3.5 门控状态机

```
           说 "Hey JARVIS"
  dormant ──────────────────► armed（awakeUntil = now + 10s）
     ▲                          │
     │ 睡眠短语 / 超时            │ 提交指令（awakeUntil 续期 10s）
     │                          ▼
  ambient 丢弃 ◄──────────  提交（转写成功）
     │ 非唤醒、非 follow-up       │
     │                          │
     │                          ▼
     │                    armed（follow-up 20s）◄── JARVIS 说完话
```

| 状态/机制 | 值 | 说明 |
|---|---|---|
| `FOLLOWUP_WAKE_MS` | 10000 | 唤醒后免唤醒词窗口 |
| `FOLLOWUP_REPLY_MS` | 20000 | JARVIS 说完话后的回复窗口 |
| 睡眠短语 | "stop listening" / "go to sleep"… | 显式回 dormant |

**关键：只有 `armed` 态内的转写才提交聊天；`dormant` 态的唤醒词只「唤醒」不「提交」。**

### 3.6 打断（barge-in / cancel-probe）

JARVIS 说话时麦克风对普通指令静音（VAD 暂停），但留一只耳朵：

```
说话中（_ttsActive = true）：
  音量 > max(BARGE_IN_FLOOR, baseline × BARGE_IN_MULTIPLIER)
      且持续 BARGE_IN_SUSTAIN_MS
      → 启动 cancel-probe 录音（最长 CANCEL_PROBE_MS）

probe 转写结果 仅与 CANCEL_RE 匹配：
  命中（cancel/nevermind/stop talking…）→ 立即切断 TTS
  未命中                           → 丢弃，TTS 继续，绝不当指令提交
```

| 参数 | 值 | 作用 |
|---|---|---|
| `BARGE_IN_MULTIPLIER` | 3.2 | 说话时声音必须显著高于底噪（回音残留过不了） |
| `BARGE_IN_FLOOR` | 0.12 | 绝对音量下限 |
| `BARGE_IN_SUSTAIN_MS` | 220 | 持续判定窗，滤掉瞬态 |
| `CANCEL_PROBE_MS` | 1600 | 探测录音时长上限 |
| `CANCEL_RE` | cancel/nevermind/shut up/stop talking… | 停止词正则 |

> 设计要点：打断是**探测式**的——不是录音就提交，而是「先听一会儿，只认停止词」，保证说话时
> 绝不会因环境声或自己的回声残留而误打断。

### 3.7 片段合并（coalescing）

VAD 常把一句话在短停顿处切成两段，直接逐段提交会导致第二段取消第一段：

```
连续片段在 STT_COALESCE_MS（800ms）内到达 → 缓冲拼接成一条 → 一次提交
```

### 3.8 前端文本过滤（提交前）

转写文本送进聊天前经过三层丢弃，全部静默：

| 过滤 | 正则 | 目的 |
|---|---|---|
| 幻觉过滤 | 镜像服务端的 YouTube 片尾语 | 兜底 Whisper 片尾幻觉 |
| 中文幻觉 | 仅对 ≤6 字短片段匹配（谢谢观看/订阅/点赞…） | 避免误杀含"识别/搜索"的真命令 |
| 填充词 | `^oh/uh/hmm/yeah…` | 语气词不触发指令、不打断任务 |
| 睡眠短语 | "stop listening" / 再见/拜拜… | 显式回 dormant |

## 4. 后端转写层（[routes.py](jarvis/server/routes.py)）

### 4.1 接口契约

```
POST /api/stt
Content-Type: multipart/form-data
字段:
  audio    —— Blob, filename="speech.webm"
  language —— "en" | "zh" | "auto" | 缺省(=en)

200: {"text": "transcribed text"}
400: {"text": "", "error": "empty audio"}
500: {"text": "", "error": "Whisper error: …"}
```

- 转写在线程池执行（`loop.run_in_executor`），**不阻塞事件循环**
- 模型访问加 `_whisper_lock`，防止与 VRAM 驱逐并发
- `language` 按请求传递，多语言模型常驻，**切语言无需重载模型**

### 4.2 模型双路径与降级矩阵

| 路径 | 模型 | 计算 | 显存 | 触发条件 |
|---|---|---|---|---|
| 首选 | large-v3-turbo | GPU float16 | ~1.5 GB | CUDA 探针通过 |
| 兜底 | small | CPU int8 | 0 | 探针失败 / GPU 加载失败 / 转写时 DLL 报错 |

**降级策略要点**：
- 加载前先探针（见 4.3），避免「GPU 模型装好、转写才崩」的陷阱
- 一旦降级到 CPU，**钉死不再回 GPU**（`_whisper_device = "cpu"`），避免逐请求来回折腾
- 转写异常分两类处理：
  - **OOM**（`"out of memory"`）→ `_vram_flush()` + `_switch_whisper_to_cpu()`，本次转 CPU，**不置永久标记**
  - **DLL 加载失败**（`cufft/cudnn/cublas/winerror 193/not a valid win32/could not load`）→ 永久切 CPU

### 4.3 CUDA 运行时探针

Windows 下检查 ctranslate2 需要的 DLL 能否真正加载（而非只看「装了 CUDA 否」）：

```python
candidates = ["cublas64_12.dll", "cublas64_11.dll", "cudnn64_9.dll",
              "cudnn64_8.dll", "cufft64_11.dll", "cufft64_10.dll"]
# ctypes.WinDLL 逐一尝试加载，成功 ≥ 2 个 → 走 GPU
```

同时把 `nvidia-cublas-cu12 / cudnn-cu12 / cufft-cu12` 这些 pip 包的 `bin/` 目录加进 DLL 搜索路径
（`os.add_dll_directory`），用户无需手动配置 PATH。

### 4.4 反幻觉转写参数

针对 Whisper 著名的 YouTube 片尾幻觉（"thanks for watching"/"subscribe"），转写参数系统性收紧
（`_stt_kwargs`）：

| 参数 | 值 | 针对的问题 |
|---|---|---|
| `vad_filter` | true | Silero VAD 先剪掉静音段 |
| `vad_parameters` | `{min_silence_duration_ms:400, threshold:0.45}` | 静音切分 |
| `no_speech_threshold` | 0.7 | 高「非语音」概率的段直接丢弃 |
| `log_prob_threshold` | -1.0 | 低置信重复输出被剔除 |
| `compression_ratio_threshold` | 2.4 | 高压缩比（重复性）输出被剔除 |
| `temperature` | 0.0 | 贪心解码，禁采样兜底 |
| `condition_on_previous_text` | false | 段间不互相影响 |
| `beam_size` | 1 | 贪心 |

`initial_prompt` 按语言分派，把 LM 往技术助手词汇上带：
- `en`：`"JARVIS command. Search, generate image, open page, run code, …"`
- `zh`：`"贾维斯 电脑指令。搜索，生成图片，打开网页，…"`
- `auto`：中英混合提示，让中文保持 CJK、英文保持拉丁，避免转写漂移

服务端后处理 `_filter_whisper_hallucination`：匹配英文 `_HALLUCINATION_RE`（含填充词）直接丢弃；
中文 `_CN_HALLUCINATION_RE` 仅对 ≤6 字短片段生效（再见/拜拜除外，留给前端睡眠短语）。

### 4.5 VRAM 管理器集成

- 模型加载前 `apply_vram_cap()`（默认上限 95% 物理显存）
- 注册驱逐/恢复回调：FLUX 等重型任务需要显存时可把 Whisper 踢下 GPU
- 默认 `EVICT_WHISPER_FOR_FLUX=0`：turbo 仅 1.5GB，与 FLUX Q6_K（~6GB）在 16GB 卡上共存，
  **STT 保持即时**；显存紧张时才开驱逐（=1）

## 5. TTS 语音合成层

TTS 与 STT 共享 `voice:` 配置，但走独立接口 `/api/tts`，三级降级。

### 5.1 后端 `/api/tts` 降级链（[routes.py](jarvis/server/routes.py)）

```
1. Piper   —— 社区 JARVIS 模型（最接近 MCU 嗓音，本地免费）
2. Riva    —— NVIDIA 云 TTS（需 NVIDIA_API_KEY）
3. Edge    —— Microsoft en-GB-ThomasNeural（电影感英式男声）
```

| 提供商 | 模型/引擎 | 媒体类型 | 响应头 |
|---|---|---|---|
| Piper | `PiperVoice` + `SynthesisConfig.synthesize_wav` | `audio/wav` | `X-JARVIS-TTS: piper` |
| Riva | NVIDIA Riva Cloud (gRPC) | `audio/wav` | `X-JARVIS-TTS: riva` |
| Edge | `edge_tts.Communicate` 流式 | `audio/mpeg` | `X-JARVIS-TTS: edge` |

`/api/tts/status` 返回当前可用提供商与配置快照，前端据此展示嗓音 profile。

### 5.2 前端 TTS（[voice.ts](web/src/lib/voice.ts)）

**双通道**：
- `speakWithServerTts`：POST `/api/tts`，失败回退浏览器 `SpeechSynthesis`
- `speakWithBrowserTts`：浏览器内置语音，`rate=0.94`、`pitch=0.82`

**流式 TTS（`streamSpeak`）**：随 assistant token 到达，检测成句（以 `. ! ?` 或换行结尾）逐句
合成入队，严格按序播放，实现「边说边播」而非「等全文结束」。

**单播放源硬保证**：
- 单个共享 `HTMLAudioElement playerAudio` 串行播放所有片段
- 每次队列变更/片段启动都 gate 在 `streamGeneration` 上；取消会 bump generation，
  所有 in-flight fetch / 定时推进 / `play()` promise 识别到 stale 后自行丢弃
- 取消顺序：先暂停 player → 清队列 → 回收 URL → 杀浏览器语音

**嗓音选择（`voiceScore`/`voiceTier`）**：按 `JARVIS_VOICE_MATCHERS` 打分排序，优先 en-GB 男性
"Ryan/George/Daniel/Oliver/Arthur"（cinematic 档），`LOWER_CONFIDENCE_VOICES` 降分，最终分档
`cinematic | british | fallback | offline`。

### 5.3 打断联动

TTS 播放/结束时调用 `mic.onTtsStart()` / `mic.onTtsEnd()`，驱动前端门控状态机在
`speaking ↔ armed` 间切换，并触发 barge-in 探测。

## 8. 设计权衡与经验

**做对了的**：
1. 动态基线 VAD 代替固定阈值 —— 一句话解决「环境吵时 VAD 卡死」
2. 唤醒词三层匹配（严格/形状/编辑距离）+ 中英双语分派 —— 抗 ASR 误听，不依赖音色
3. 打断用探测式 cancel-probe —— 既打断又绝不误提交
4. 反幻觉双端过滤（服务端参数 + 前端正则兜底）
5. 降级后钉死 —— 避免逐请求反复试 GPU/CPU
6. TTS 流式成句播放 + 单播放源 generation 门控 —— 边生成边播，取消不残留

**容易踩的坑**：
1. 关掉 `echoCancellation` —— 立即自我对话死循环
2. 每段都提交而非合并 —— 一句话被切成两条互相取消
3. 只在服务端判断是否该理 —— 环境声全进 LLM，既烧钱又误触
4. 显存不够还硬上 large-v3 —— 换 turbo，用质量换「能常驻」
5. 中文幻觉用 `\b` 边界匹配 —— CJK 字符不是 `\w`，边界永远不命中

## 9. 扩展指南

- **加语言**：后端 `_stt_kwargs()` 的 `language` 加对应语言码 + 对应 `initial_prompt`；前端
  `detectWake`/`stripWakeWord` 加对应语言分支，唤醒词正则 + Levenshtein 基线词按目标语言读音重写
- **换模型**：`_get_whisper_model()` 里换 `WhisperModel` 参数即可，注意显存预算
  （large-v3 全量 ~3GB，turbo ~1.5GB）
- **自定义唤醒词**：改 `WAKE_STRICT_RE`/`WAKE_SHAPE_RE`/`WAKE_ZH_RE` 与 `levenshtein` 基准词，
  并同步睡眠短语（把唤醒词塞进去让用户能睡回来）
- **离线兜底**：把 `GET /api/stt` 换成本地 WASM 转写（whisper.cpp）可完全离线，
  前端 VAD/门控逻辑不变 —— 采集层与识别层本就解耦
